## 1. 项目概述

### 1.1 背景

前五讲的教学内容有一个共同特征：**结论都很短，但结论背后的"为什么"依赖对底层数据的直观感受。** 例如"卷积是邻域加权和""均值滤波治不了椒盐噪声""uint8 会回绕""删掉 Normalize 掉 11 个点"，这些结论用 PPT 讲十遍，学生记住的仍是一句口号；只有让学生**看见 9 个数字被乘、被加、被排序**，看见矩阵里的 255 变成 4，结论才真正落地。

现有教学手段的三个缺口：

1. **静态截图无法体现"过程"**：滑窗怎么走、排序怎么排掉极值、CLAHE 的直方图怎么被限幅，静态图只能给结果，给不了过程。
2. **参数与现象的因果链断开**：学生调 ksize、调 clipLimit，看不到同一张图的矩阵、直方图、指标如何同步变化。
3. **代码与画面脱节**：学生知道 `cv2.GaussianBlur(img,(3,3),0)` 这一行，但不知道这一行在像素层面发生了什么。

### 1.2 产品定位

一个**面向课堂演示与学生课后自学的单页可视化教学软件**。以"一张图、一台仪器"的方式工作：选定一张图，选定一个算子，拖动参数，同时看到**画面、矩阵、参数、代码**四个视角的实时联动。

一句话定位：**把教案里的每一个"为什么"，变成学生可以自己拖出来的现象。**

### 1.3 设计原则（贯穿全部功能）

| 原则 | 含义 | 落地要求 |
|---|---|---|
| 四区同步 | 任何一次参数调整，四个区域在同一帧内全部更新 | 联动延迟 ≤ 100 ms（512×512 以内） |
| 过程可回放 | 关键算法必须能单步、能慢放、能回退 | 滑窗、排序、阈值连接、流水线逐环节均可单步 |
| 代码即事实 | 界面上展示的代码必须是真的能跑的代码 | 纯 Python + OpenCV/NumPy，一键复制可直接运行 |
| 结论可对照 | 每个操作都能"改前/改后"对照，而不是只看改后 | 差分图 + PSNR/SSIM + 直方图叠加 |
| 错误可演示 | 教案强调的"静默错误"必须能被主动演示出来 | 提供"错误示范"开关（uint8 回绕、BGR/RGB、HWC/CHW、顺序颠倒） |
| 可扩展 | 第 6 讲起的 CNN/检测/分割要能接进来 | 统一算子注册接口 + 张量抽象 + 推理后端插槽 |

### 1.4 非目标（本期不做）

- 不做在线判题、账号体系、成绩管理。
- 不做模型训练（第 6 讲以后通过推理后端接入预训练模型，本期只留接口）。
- 不做移动端适配（教室投影 16:9 与个人电脑 1440p 为主，最小支持 1366×768）。
- 不复刻 OpenCV 全部 API，只覆盖前五讲出现的算子。

### 1.5 使用者与场景

| 角色 | 场景 | 关键诉求 |
|---|---|---|
| 主讲教师 | 课堂投影讲授，90 分钟按讲稿节奏推进 | 一键切换知识点、全屏、字号大、可暂停在某一帧讲解 |
| 学生（课堂） | 跟随演示，边看边记 | 现象足够醒目，参数变化方向明确 |
| 学生（课后） | 对照作业自己复现（如"两种噪声 × 三种滤波"） | 预设一键还原、结果可导出、代码可复制 |
| 助教 | 实验课验收，指着某一行代码提问 | 代码区能定位到"当前这行在算什么" |

## 3. 总体设计

### 3.1 核心机制：四区联动（Single Source of Truth）

整个软件只有**一份状态**，四个区域都是它的视图：

```
State = {
  source:      ImageBitmap          // 原图（不入缓存破坏）
  pipeline:    Step[]               // 有序的算子链，每个 Step 有 type + params + enabled
  cursor:      number               // 当前查看第几步的产物
  probe:       {x, y}               // 像素探针位置
  channel:     'gray' | 'r' | 'g' | 'b' | 'h' | 's' | 'v' | 'r'
  view:        'side' | 'slider' | 'diff' | 'overlay'
  trace:       TraceFrame | null    // 当前算子的执行轨迹（用于 D 区高亮与 B 区动画）
}
```

- 改参数 → 只重算 `pipeline[cursor..end]` 之后的步骤（前缀缓存）。
- 移动探针 → 只更新 B 区高亮与数值，不重算图像。
- 播放轨迹 → 按 `trace` 的帧序列驱动 B 区动画和 D 区高亮，与图像计算解耦。

## 5. 深度学习扩展接口规范（草案）

```ts
// core/tensor.ts
export interface Tensor {
  data: Float32Array | Uint8Array | Uint8ClampedArray;
  shape: number[];                 // HWC:[H,W,C] CHW:[C,H,W] NCHW:[N,C,H,W]
  layout: 'HWC' | 'CHW' | 'NCHW';
  dtype: 'uint8' | 'float32';
  min?: number; max?: number;      // 缓存统计，供热力映射
}

// operators/registry.ts
export interface OperatorSpec<P = any> {
  id: string;                      // 'filter.gaussian'
  label: string;                   // '高斯滤波'
```

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 自研算法与 OpenCV 结果有偏差 | 学生对照代码时困惑 | 每个算子写"手算用例"单测；对 Canny/CLAHE 这类复杂算子，优先对齐 OpenCV 的公开公式，界面标注"教学实现，与 OpenCV 存在 ≤ 1 灰阶差异" |
| 课堂现场卡顿/翻车 | 影响教学 | Worker + 前缀缓存 + 降采样；提供"轻量模式"（图像上限 384×384） |

| 教案后续调整 | 需求返工 | 知识点与讲次解耦，模块化（`modules/Mx.ts`） |
| 素材版权 | 无法发布 | 全部程序生成 + 用户自备上传 |
